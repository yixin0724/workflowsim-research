## 执行工作量与证据契约

新运行记录 `configuration.executionSemantics=WORK_CONSERVING_TASK_EXECUTION_V2`。旧 v4 缺少该字段时仍可读，但不能冒充修正后执行模型。

- `TaskExecutionModel` 统一规划/运行的矩阵换算：`round(executionSeconds × vmMips)`；没有矩阵时使用原始单 PE MI。有矩阵却缺坐标时明确失败。
- `TaskOutcome.lengthMi` 和任务事件的 `taskLengthMi` 保留原始声明；新增 `effectiveExecutionLengthMi` 表示当前尝试实际采用的计算量，不含 stage-in。
- Job 保存注入 stage-in 前的计算量，重试不能复制已经加长的信封。STATIC 重试的数据准备开始前必须具有目标 VM。
- 总工作量的 `perPeMi × pes × 1_000_000` 必须可由 signed long 表示；非法大值不静默饱和成另一段执行时间。
- 最小事件间隔仍影响事件完成/派发量化，但不授权在任务到达前累计 CPU 工作。
- WED 对每个非空释放批次抽样一次，按子批次累计延迟；零间隔不拆分，正间隔是最大批大小，尾部不足一批也应用延迟。零数据路径统一进入普通批次，不单独改变随机抽样。

## PEFT 一级来源新发现

已取得作者 Hamid Arabnejad 的[公开博士论文机构记录](https://repositorio-aberto.up.pt/handle/10216/92290)及[公开全文](https://repositorio-aberto.up.pt/bitstream/10216/92290/2/129782.pdf)。第 3 章封面明确收录 DOI `10.1109/TPDS.2013.57` 对应的 TPDS 25(3):682–694 文章。

印刷第 71 页（PDF 第 83 页）式 (7) 为后继执行成本递推：

```text
OCT(t,p) = max_child min_q [OCT(child,q) + w(child,q) + c(t,child,p,q)]
OCT(exit,p) = 0
```

同处理器通信为零；第 73 页式 (9) 使用 `OEFT=EFT+OCT`，Algorithm 1 明确使用就绪表与插入式 EFT。当前 LOCAL 实现的“自身 w + 后继 OCT，出口为平均计算成本”不符合该来源，不能解释为仅改变一个出口常数。

该文 Table 5/6 与图 2 的示例为 PEFT 122、HEFT 133，而不是仓内旧 HEFT 算例上的 76/80。现已通过系统 OCR、同源字形和 SVG 几何解码得到图 1 全部矩阵/边，再由不调用生产代码的 Fraction 脚本逐项核对 Table 5/6。真正论文测试的 OCT、rank、选择顺序、VM、Job/Task 区间及绝对终点 232.1/243.1 已通过；旧 HEFT-origin 输入在正确 Eq7 下为 85（绝对 195.1），单独保留回归，不能再称为该论文算例。本模型不支持图像输入，因此不宣称完成了人工视觉核验。
