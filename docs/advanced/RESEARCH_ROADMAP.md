# 科研工作流模拟器演进路线图（Research Roadmap）

> 状态：**规划中**（本文档随轮次推进持续更新）
> 创建日期：2026-09-11
> 维护约定：每完成一个轮次，将对应条目从「计划」移入「已完成」并记录实测结论与证据位置。

## 一、定位与诚实边界

本平台是**受控、确定性、无争用的抽象环境**下的工作流调度模拟器。这一边界适合做算法
语义对比与论文复现（见 `docs/algorithms/CATALOG.md`），但以下问题域当前**无法**回答：

- 多任务并发传输下的调度权衡（链路争用未建模）；
- 多租户/混部场景（单 JVM 单工作流串行执行）；
- 超售（overcommitment）下的 Host 层 CPU 干扰；
- 在线到达流调度（DAG 在 t=0 全量已知）；
- 能耗与绿色计算方向；
- Spot 实例、抢占与弹性伸缩。

下列各轮次的目标就是在不破坏现有语义承诺的前提下，逐块补齐这些能力。

## 二、轮次规划（按推荐顺序）

### R1：多 seed 统计框架 + 显著性检验 —— 计划中

**动机**：现有黄金值均为单 seed 锁定。单点数值不构成统计结论；发表级算法对比需要
n≥30 seeds 的分布描述 + 假设检验。这是投入产出比最高的一步：不改变任何模型语义，
纯增量能力，却让现有全部算法轨道立刻产出统计上站得住的对比结论。

**交付内容**：
- 统计实验框架：给定配置工厂 + 平台 + seed 集合，批量运行并聚合指标分布
  （均值/标准差/最小/最大/分位数）；
- 成对显著性检验（Wilcoxon 符号秩检验，基于已有 commons-math3 依赖）；
- 结果写入 manifest 证据链（与现有证据体系一致）；
- 测试覆盖：分布聚合正确性、检验的显著/不显著双侧判定、逐 seed 确定性。

**验收标准**：框架自身测试全绿；能对一个真实算法对（如 MINMIN vs FCFS）输出
带 p 值的对比报告。

### R2：链路争用带宽模型 —— 计划中

**动机**：当前带宽模型无争用、无拓扑（任意 VM 对 `min(bw)`），无法研究数据感知
调度的核心问题。

**方向**：共享链路带宽池 + 排队模型；与 LOCAL_HEFT/CPOP 轨道的通信感知语义衔接。

### R3：故障模型统计检验 + 覆盖率门禁 —— 计划中

**动机**：补齐测试审计 P1 遗留项。

**内容**：
- 故障到达过程是否服从声称分布的 KS 检验；
- JaCoCo 覆盖率报告与阈值门禁。

### R4：DRL 调度器轨道 —— 计划中

**动机**：深度强化学习调度是当前工作流调度发文量最大的方向。平台的确定性事件循环
天然适合做 RL 环境封装（状态 = 就绪队列 + VM 负载，动作 = Job→VM，奖励 = 负
makespan）。

### R5：多工作流并发 / 动态到达 —— 计划中

**动机**：解锁多租户与在线到达场景研究。

## 三、长期候选项（未排期）

| 方向 | 说明 |

## 四、执行纪律（所有轮次共同遵守）

1. **每轮单独分支**，PR 合并后清理；
2. **做完必须测试**——新增能力必须附带测试，且完整门禁（`mvn verify`，JDK 17）
   全绿后才算完成；无测试的交付不算完成；
3. **CI 强制验证**：每个 PR 在 GitHub Actions 上全绿才可合并；
4. **不改变既有语义承诺**：黄金值、manifest 契约、已声明的平台边界只能扩展，
   不能静默变更；确需变更时在文档与 PR 中显式记录；
5. **诚实记录边界**：每轮新增能力的适用范围与已知限制写入对应文档
   （CATALOG / 本路线图 / 模块 Javadoc）。
