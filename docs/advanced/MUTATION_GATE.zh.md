# 变异门禁（Registered-Mutant Survival）

[English](<MUTATION_GATE.md>) · **简体中文**

变异门禁是**测试集诚实度检查**，不是覆盖率工具：它验证维护中的测试集仍能*杀死*每一只注册的语义变异。绿灯只有当"语义被破坏时测试真的红"才有意义；本门禁在核心决策面上逐轴证明这种灵敏度——每轴一只注册金丝雀。

注册集合**维护在代码里**（[scripts/mutation-gate.py](<../../scripts/mutation-gate.py>) 的 `REGISTRY`），本页记录范围、用法与台账政策。概念与最初九只金丝雀由 2026-10 变异试点（工程档案）验证：两只幸存变异暴露了真实测试盲区（流体完成容差放大、平衡合并丢失解链），当时即以专门的边界/守恒测试关闭。

## 注册变异台账（范围）

| ID | 注入的语义破坏 | 守护轴 |
|---|---|---|
| M1 | HEFT 向上 rank 取首子而非最大子 | 规划 rank 计算 |
| M2 | MCT 丢弃 availability 项 | 静态独立任务成本模型 |
| M3 | 依赖门控反转（未满足才放行） | 引擎依赖门控 |
| M4 | Fat-tree 聚合下标取 `halfK` 而非 `availableAggregateCount` | 拓扑路由确定性 |
| M5 | 流体完成容差放大 1000 倍 | 数值容差边界 |
| M6 | MI 换算在解析边界 floor→round | 输入量子化语义 |
| M7 | 平衡合并丢失子侧解链 | 聚类守恒律 |
| M8 | 在线绑定计算估计减半 | coherent 绑定名义分数 |
| M9 | 任务执行窗口偏移 1e-6 秒 | 时序窗口精确性 |
| M10 | SHARED DLS 动态层把最早开始减法翻转为加法 | DLS 决策面 |
| M11 | 注册声明 ANY 范围不再覆盖任何文件系统 | 注册声明语义 |

集合刻意小而**注册在案**：它守护承载研究主张的语义轴，不是全代码库的穷举变异分。一轴一只；增长按下方政策的显式登记。

## 用法

```bash
# 全量（约 3–5 分钟；需干净 Git 树并独占运行——勿并行构建）
python3 -B scripts/mutation-gate.py --output <新报告.json>

# 仅台账 + 锚点活性（不变异、不调 Maven；轻量周期预检）
python3 -B scripts/mutation-gate.py --output <新报告.json> --dry-run

# 按 id 子集
python3 -B scripts/mutation-gate.py --output <新报告.json> --ids M5,M9

# 便捷目标（报告落入 git 忽略的工程档案区）
make mutation-gate

# 自测（不涉及 Maven）
python3 -B scripts/test-mutation-gate.py
```

退出码：**0** 全部注册变异被杀；**1** 有幸存或变异应用期间构建基础设施失败；**2** 至少一个注册锚点漂移（源码已变，须先修台账）。报告为 JSON，只写入尚不存在的新路径（never-overwrite，与独立审计器同纪律）。

## 执行模型与安全

- 每只变异**就地**应用于工作树；目标文件在 `finally` 块以内存备份还原，并逐字节校验相等。
- 全量模式在 `git status` 脏时拒绝启动。
- 每只先跑注册**杀手测试集**（快）；未杀则升级全 simulator 模块测试。仅当 Maven 非零退出**且**有测试失败才算 KILLED；无测试失败的非零退出是 INFRA_FAILURE，不是击杀。
- 锚点唯一性：每个注册锚点必须在当前树中**恰好出现一次**。机械重构会使锚点漂移——门禁退出码 2 并指出变异 id；把锚点更新为现行文本（漂移修复不是语义变更）。
- 中断恢复：干净树前置使恢复确定——若运行中途被杀，留下的唯一脏文件**就是**被应用的变异；`git checkout -- <file>` 还原后**前台**重跑。本门禁绝不可作为可杀后台任务运行。

## 扩表政策

1. 在 `REGISTRY` 登记：唯一 `M<n>` id、含因果的 `name`、目标 `file`、树内唯一的 `old`/`new` 锚点、杀手测试类。
2. **红先行**证明击杀：单跑该 id 并记录 KILLED。
3. 在本页台账表补充守护轴。
4. 若后续机械重构改写锚点，修复锚点而不改变异语义；干跑预检让漂移检测成本极低。

为修复*幸存*金丝雀而扩表意味着发现了缺口：先写失败的杀手测试（期望值遵循本仓三源规则：文献/契约/守恒律），再登记被其杀死的变异。
