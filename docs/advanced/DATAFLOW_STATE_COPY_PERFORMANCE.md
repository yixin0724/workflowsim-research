# NF006：数据流事务历史复制优化

## 目标与不变项

本阶段只优化内部状态的复制和查询范围，不修改V1/V2/V3物理模型、来源/路由选择、流体分配器、VM绑定策略、浮点聚合顺序、事件记录预算或任何研究输入/黄金结果。基线为已发布的`c1e2893`，实现分别提交为`c162d15`（不可变副本历史）和`7215dbd`（活动/终态Job拆分）。

原实现每次事务复制所有历史Job、已完成Task/Job观察和全部文件副本行；输入选择又重复取得全量副本快照。即使没有文件或网络服务，链式任务也会出现近二次的累计分配与耗时。

## 实现

- [内部历史索引](<../../simulator/src/main/java/org/workflowsim/data/v2/PersistentHistoryMap.java>)以不可变二进制归并块共享历史。层级按**写入数**而不是去重后map大小计算；新写覆盖旧值，查找从较新层开始。根、块及其值不可变，不向外提供迭代/删除接口。
- [副本状态](<../../simulator/src/main/java/org/workflowsim/data/v2/DataReplicaState.java>)只复制发生新发布的那个文件的有序位置行；完成记录与Job观察共享不可变根。fork仍单独复制活动复制索引，保留分支独立时钟、序号及票据身份。快照捕获不可变根，不再枚举全部历史缓存。
- [运行协调器](<../../simulator/src/main/java/org/workflowsim/data/v2/CoherentDataflowRuntime.java>)只在事务中复制活动Job；输出处理全部成功后才把完成尝试归档为不可变查询摘要。历史准备结果保持同一对象，准备时差仍按原始时刻相减。重复Job ID检查覆盖活动与终态两侧。
- 活动观测及静止判断不再遍历已结束Job；就绪队列、输入等待者、SOURCE等待、输出义务和活动复制的屏障与顺序保留。

历史索引查找检查O(log W)个块（假定预期常数哈希查询），更新沿单条历史摊销复制O(log W)项；单次大归并仍可能O(W)。重复分叉的大归并不共享摊销。因此这里不宣称单次更新最坏情况对数复杂度。

没有改造已经采用增量追加的生命周期日志，也没有取消checked服务的事务副本。活动工作集仍需要隔离；宽任务批次并未被宣称线性化。

## 测量方法

[可重复基准](<../../simulator/src/test/java/org/workflowsim/data/v2/DataflowStateProfile.java>)用**同一已编译测试类**分别加载冻结基线JAR与候选实现。两侧使用相同JDK17、`-Xms512m -Xmx512m`、输入生成规则、时刻和三次采样；每组先预热三次100任务。

- 测量范围为协调器状态转换（在线场景含绑定、观察和预留打分），包含重复静止/空文件范围观察；不包含文件计划构造、初始化、最终语义编码与指纹计算。
- `threadAllocatedBytes`是测量线程的**累计分配字节**，不是常驻内存、峰值RSS或所需堆容量。`heapPoolPeakSumBytes`是各堆内存池峰值之和，也不冒称同一时刻的进程峰值。
- FILELESS是无文件链；FILES_V2为逐任务独立外部输入/输出、缓存集合持续增长的链（不是高命中率负载）；STORE_V3加入受限读写与输出落库；ONLINE_V3再加入控制就绪绑定；WIDE_V2为大量同时活动的无文件任务。
- OFF、完整捕获及预算1截断均有固定对照。所有采样分别校验状态、捕获和在线动作SHA256，不用性能容差替代语义比较。

本次完成**102对采样**，每一对的状态、捕获及动作指纹完全一致。下表是同一台机器上的中位数，不是普遍平台校准或统计显著性结论。

无文件链从1000到2000任务，累计分配由基线约1144→4548MiB改为约19.46→36.56MiB；到4000任务为68.46MiB，而基线为17373.23MiB。V2文件链优化后1000→2000任务耗时约20.55→38.41ms，在线V3约39.81→82.03ms。该组测量符合消除历史全拷贝后的预期，但不是所有输入复杂度的证明。

**保留的限制：**WIDE_V2在1000个同时活动任务时，累计分配仍约656MiB（基线1106MiB），250→500→1000任务仍近二次增长。这里的成本来自确实仍需隔离的活动Job集合，不应归入“已解决的历史复制”。输入解析、完整验证、报告生成、活动流求解和大规模候选评分也不包含在上述加速结论内。
