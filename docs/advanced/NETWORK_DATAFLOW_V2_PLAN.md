## 3. NF-001先锁定的精度契约

- 保留无参引擎构造器，默认OFF；显式正记录预算才启用。OFF不记录历史，不改变原分配、完成顺序或错误校验。
- 快照状态 `DISABLED/COMPLETE/TRUNCATED` 描述**记录是否完整**，不代表所有传输已完成。超预算保留确定前缀并报告丢弃数量，不把截断账本用于完整网络结论。
- `observedTime` 为外层advance/addTransfer调用声明的now；`effectiveTime`为内部流体事件时刻。容量注册API没有now，只能记录引擎已知时间，不能虚构外部时钟。
- 服务区间保留原积分elapsed、速率与扣减前/后剩余量。double时钟的end−start不必等于elapsed，不用新观察代码“修复”原算式。
- completion单列数值结算残余；不把容差移除和强制清零的字节虚构为实际服务。资源守恒使用速率面积，流余额守恒独立计入数值残差。
- solver中临时归零/渐进填充不逐步冒充有效速率；只记录已验证的最终分配变化。
- 保留资源列表顺序和重复键语义；以内部入流实例编号区分旧API允许的完成后外部ID复用，不因记录功能新增拒绝行为。
- 先采用有界内部buffer，而非可执行用户observer/Clock回调，避免记录代码通过异常或重入改变引擎。

## 4. 旧行为与新行为隔离

- 旧五种模型继续作为兼容基线。需要改变SOURCE预算、实际来源、释放时刻或副本可见语义时，必须进入明确V2路径，不悄悄覆盖旧实验。
- OFF时旧configuration、metrics、主events和manifest中不增加false/null字段或新角色，防止破坏既有精确rerun契约。
- NF-002优先采用显式opt-in、独立版本sidecar。新sidecar必须同时获得内容校验和rerun比较支持，不能仅靠hash/size验证就称逐流账本已认证。
- 旧争用引擎以父组聚合文件：NF-002应明确“组级流”，不能虚构未建模的逐文件FCT。V2逐文件/实际来源语义另行验收。
- 主事件流保持当前CloudSim观察时刻，不向其中插入追溯的物理完成时间。迟到观察和真实内部完成必须可区分。

## 5. NF-002分步交付约束

- **NF-002A（已完成阶段）**：先让Java API可开启记录，将传输组与Job/Task、被约束来源和资源关联，并在会话清理前取得深不可变快照。OFF仍不增加旧工件字段。ON尚未完成sidecar导出时，原工件写入入口必须明确拒绝，而不是静默丢弃用户请求的账本。
- **NF-002B**：在A的测试通过后，实现完整/零流/截断的网络指标、独立版本sidecar及内容校验。只校验hash不算网络语义验证；数值残差不等于传输流量。
- **NF-002C**：严格配置重建与sidecar逐字段rerun比较；截断账本即使IDENTICAL_CORE也不得称完整网络认证。
- **NF-002D**：最后接通Workbench配置、正常run及standalone报告显示，验证离线、安全文本、大编号和预览上限。

上述子功能各自有定向与集成门禁，不能提前把NF-002A的内存快照称作已完成的用户工件导出。新版本模型与在线调度物理语义不在NF-002中改动。

## 6. 网络验收的最小独立场景

单流、两流共享/不共享瓶颈、名义上限与多瓶颈释放、反向/重复资源占用、同时完成、迟到advance、源节点瓶颈、多副本实际来源、LOCAL命中、fan-in释放、输出上传、动态派发等待和不同事件间隔敏感性。核心结论须来自账本与独立算式，而不是只看最终makespan。
