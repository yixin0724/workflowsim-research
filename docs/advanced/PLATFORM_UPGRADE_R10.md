# R10 平台升级与验收记录

本轮按“研究可信度 → 扩大实验 → 统一操作与报告”顺序实施。Java 侧只负责仿真环境、策略接入、动作校验和证据；不建设神经网络、训练器或模型训练流程。

## 阶段一：研究语义与证据

- manifest 升级为 v4：完整保存输入顺序、提交时刻、原始任务×VM执行秒数矩阵、网络拓扑原始声明和传输开始/公平分配语义；provenance 仍为 v3。旧 manifest v2/v3 继续只读兼容，不补造缺失条件。
- LOCAL_CPOP 修正 rank_d：入口为零，其他任务沿前驱累加前驱平均计算时间和入边平均通信时间。关键路径同时满足 rank_u + rank_d 等于关键路径长度，以及所选边的 rank_u 递推等式；平局按任务 ID。新增手算链、论文算例、等长路径、跨分支捷径、单 VM 和同对象复用测试。
- 端点/Fat-tree 流体网络改为带名义速率上限的 max-min progressive filling，回收被其他瓶颈限制的流所留下的份额。积分跨过完成时点时分段推进并重分配；引擎统一消费新流登记与检查事件返回的完成列表。
- 语义变化会改变旧黄金值。旧 R8/R9 研究结论只作为历史记录；保持原实验参数，不能为维持旧排名调整带宽或算法。网络模型增加约束后并非每一条流、整个 DAG 的完成时间都必然单调，测试应锁定资源守恒和有依据的具体算例。
- 同步当前入口文档，区分兼容教学代码与标准研究入口。

阶段验收：字段完整性与非法字段测试、历史兼容、手算语义、端到端任务完成与事件结算、两个模块完整 verify。

## 阶段二：网络受限调度研究

扩大工作流家族/任务规模、资源规模和随机种子；参数矩阵预先声明。确定性 HEFT/CPOP 的相同结果不能作为多个独立样本。跨 DAG 推断先对每个 DAG 的随机重复汇总，再在同平台和同网络模型下配对；展示效应幅度、胜平负和多重比较调整，保留零差值及负面结果。

完整研究与 CI 分离：常规 CI 使用小型真实执行矩阵；正式研究显式启动，逐运行保存可校验证据和版本身份，汇总记录完整性可独立检查。旧360次 campaign 仍是独立的历史协议。

阶段验收：矩阵、种子、分组与统计单元测试；小矩阵端到端集成；正式矩阵执行、逐工件校验与结果复核。

## 阶段三：统一操作入口与报告

提供严格 JSON 配置入口、预检、运行、实验历史、证据校验和自包含 HTML 报告。结果页面展示概览、配置范围、任务执行时间线、VM 利用率、任务依赖摘要和同条件方案对比。报告可离线打开，不需要训练服务或额外数据库。

不同实验采用独立目录，拒绝无意覆盖；记录失败运行状态，禁止把不完整结果列为成功。模型条件不同的方案不得悄然混排。HTML 必须转义用户输入，静态报告不依赖 CDN。

阶段验收：非法配置、目录覆盖、路径、HTML转义、报告数据一致性、失败记录、历史扫描和同条件比较测试；用户命令入口子进程冒烟。

## 最终联合验收

1. 配置 → 运行 → v4证据 → 校验 → 历史 → 报告的完整链路。
2. 网络×算法×数据输入×资源规格的代表性组合与重复运行。
3. Maven clean verify：单元、语义、两个模块集成、示例子进程、覆盖率门禁；不降低既有阈值。
4. 正式研究输出与最终源码版本一致，检查无临时源码/测试数据污染。

## 仍然适用的边界

- 统一入口是严格JSON/CLI加离线报告，尚无网页启动仿真服务、账号或多租户管理；报告本身不需服务器。
- 常用无故障/无额外开销实验可使用JSON入口；其他受支持高级研究通过完整Java API。配置未知字段会拒绝，不会静默忽略。
- 网络为流级抽象，时间和成本未由真实云校准；静态规划仍按无争用估计，在线/RL策略不能直接搭配当前静态映射网络轨道。
- 正式研究只有5个经典DAG与2个合成DAG，多重比较调整后没有普遍优势的统计证据。数据来源及解析器首次INPUT尺寸优先的兼容规则已在协议说明。
