# NF003：一致的数据流V2契约与分步验收

## 当前实现边界

NF003先独立验证A1/A2/A3组件，再由NF003B接入真实Kernel与独立证据闭环。当前已开放`COHERENT_FILE_DATAFLOW_V2`和`COHERENT_FILE_DATAFLOW_NO_CONTENTION_V2`两个新Kind。旧五个模型、`is*V1`判定、V1组级账本、旧研究参数和黄金结果保持原义。

[逻辑文件计划](<../../simulator/src/main/java/org/workflowsim/data/v2/DataflowFilePlan.java>)、时间化副本状态和冻结来源/路径由[运行协调器](<../../simulator/src/main/java/org/workflowsim/data/v2/CoherentDataflowRuntime.java>)统一管理。新模型通过SimulationRunner及Workbench运行、独立文件生命周期侧车导出、Java/Python校验、rerun和专用离线报告连接起来；不是给旧执行路径换标签。

初始支持矩阵是RANDOM静态映射、STATIC派发、LOCAL、NONE聚类（每Job一个逻辑Task）、无开销和受控NOOP重试。平台可无拓扑或使用Fat-tree；Java运行器在构建前限定偶数k为2..32，Workbench保留原2..16限额。容量与时间在V2检查路径上要求可表示，违反数值支持域会原子拒绝。共享与独立服务保留相同的单流路径约束及生命周期规则。

后续NF005为相同物理V2增加显式`CONTROL_READY_ONLINE_ASSIGNMENT_V1`配置分支：INVALID预规划、控制就绪时绑定VM、随后输入准备，CPU仍用STATIC。它不改变上述默认RANDOM分支、逐文件来源/路径或V2侧车语法；额外动作认证要求完整生命周期，参见[在线绑定契约](<ONLINE_DATAFLOW_ASSIGNMENT_V1_CONTRACT.md>)。

## A1：深冻结的逻辑文件与生产者索引

契约标记：`SCOPED_RESOLVED_WRITE_ONCE_FILES_V2`。

- 文件身份为`(workflowInputIndex, existingResolvedFileKey)`，不是FileItem对象身份、Job ID或实际持有副本的VM。
- 保留解析器已有文件键；不重复添加命名空间，也不通过拆分文件名猜测工作流。多输入解析器当前会产生`workflow-<index>/...`键。
- 一个逻辑文件至多有一个逻辑Task生产者；生产者必须是消费者的控制祖先，不限直接父节点。同Task原地读写和歧义多生产者拒绝，而不是当作外部SOURCE或猜一个父Job。
- 尺寸是当前解析结果中保留下来的有限、非负binary64字节数；同身份的所有保留描述必须完全一致，不设epsilon。零字节保持为有引用的零需求，不能变成“无输入”。
- **这不是原始输入声明检查器**：DAX解析器已经按first-wins合并的输入尺寸差异无法在此恢复。A1明确使用resolved-size语义，不宣称那些丢失的原始声明已经通过一致性检查；旧解析器不会被顺带收紧。
- 在聚类清空任务列表前捕获；复制逻辑ID、工作流归属、文件元数据和引用计数，不保留可变Task/FileItem。验证不调用会改变Task.depth的DAG深度分配器。
- `demandsFor(logicalTaskSubset)`按逻辑文件去重，但保留所有输入引用计数及消费Task集合。选择内生产者所产生的输入属于内部需求；重试可用原逻辑Task子集再次求需求，不遍历历史父Job输出列表。
- 引用字节数使用精确binary64输入BigDecimal乘以计数，允许大于Double.MAX_VALUE的合计；它不是实际传输的唯一载荷。
- 图验证和所需生产者祖先检查使用迭代遍历，不存储全对祖先矩阵。构建可能需要按消费者遍历祖先，活内存随图与文件/引用规模线性增长。

A1允许纯空计划/空Task选择；这不放宽现有仿真入口对合法工作流的要求。数据流运行初期仍计划保留静态目标绑定与已有的聚类支持边界，纯Task集合规范化不代表已实现新的聚类执行语义。

## A2：带出处与观察时刻的副本状态

[副本状态组件](<../../simulator/src/main/java/org/workflowsim/data/v2/DataReplicaState.java>)和[类型化位置](<../../simulator/src/main/java/org/workflowsim/data/v2/DataLocation.java>)独立于旧ReplicaCatalog；由V2运行协调器调用，不改变旧模型目录行为。

- VM与SOURCE是不同类型的身份，SOURCE标签不能伪装成VM ID。初始化已知位置集合后，未知位置不能默认为有效持有者。
- 每个副本保存最早可见时刻、当前获取方式、根生产Task/Job尝试/实际位置/发布观察，以及直接复制来源与票据编号。重复成功尝试不覆盖已有副本的最早出处。
- 同一Job尝试必须具有一个实际VM和一个完成观察时刻；其组成Task可有不同成功结果。失败Task不发布文件，计算失败不删除已到达输入。冲突回调在任何状态改变前拒绝。
- 活动复制票据与逻辑文件、所选可见副本、目标和准入时刻绑定；不能跨run使用，未结算票据不代表目标副本已经可见。票据只证明状态准入，**不校验网络服务或推断内部流体完成时刻**。
- 同文件/目标至多一个活动票据；协调器应先查询并加入该票据，再决定是否需要选择新来源，不能静默创建重复复制。不同目标仍分别准入。
- 正复制在严格晚于准入的实际观察时刻结算；无有限后继时刻的正准入拒绝。零字节仍需真实可见来源，但立即解析且不消费正复制编号。
- 读取快照不会推进时钟，也不暴露可变状态。非法请求不改变观察时钟、副本、完成计数或复制编号；合法失败结果仍是一次观察，会推进观察水位。

## A3：冻结的真实来源与资源路径

[资源/放置视图](<../../simulator/src/main/java/org/workflowsim/data/v2/DataTransferFabric.java>)与[来源选择器](<../../simulator/src/main/java/org/workflowsim/data/v2/ReplicaTransferSelector.java>)使用A2可见性快照中的权威文件定义和副本，返回同一个不可变来源/路径/独立速率决策，不修改副本状态。

- 结果明确区分缺少来源、本地已有、零字节引用与正网络复制；缺少来源不是零成本成功。
- 端点容量输入单位为B/s；Fat-tree适配器使用已构造的不可变拓扑和实际VM→Host映射，资源次序为源VM、拓扑链路、目标VM。不同VM即使同Host，也包含两个端点约束。
- SOURCE输入在NF003明确不设汇聚容量且不经过fabric；未知来源或物理资源拒绝。到SOURCE的输出路径未在A3开放，属于NF004。
- 当前纯视图支持正normal有限binary64容量；所选正传输独立秒数与绝对完成预测必须有限且推进时钟。不将下溢当零传输、不为数值问题改选更慢来源。
- **这些单流检查本身不是共享求解器证书**。V2驱动另行检查每次活动共享分配、有限速率面积、结算残余与未来时刻，并用事务化暂存处理失败；在构建原FatTreeTopology前也有新模型安全尺寸/容量预检。
- 无共享机理测试先用不同逻辑文件和相同路径/容量验证；现已通过独立Kind接入同一个Kernel生命周期，只在跨流共享开关上不同，不移除单流瓶颈。

运行接线使用这些显式状态和决策，而不是给旧站点字符串增加猜测含义。

1. 区分逻辑生产者与发布副本的Job尝试；只在实际完成后的成功Task输出发布点登记，位置来自实际Job VM，不读提交时预测的Task.finishTime。
2. 每个文件副本都有可见时刻。目标副本必须在该文件实际结算时才可见，不能等整个Job所有输入完成后一起冒充同时到达。
3. 选择规则初始采用：可见本地副本优先，否则最大独立路径瓶颈速率，稳定端点顺序打破平局。不使用瞬时队列做自适应路由。
4. 返回不可变的文件身份、载荷、所选副本来源/发布出处、目标、完整资源路径与独立速率上限；估时、准入、计费和证据使用**同一份决策**，不再按生产者重新构造另一条路径。
5. 物理路径资源缺失必须拒绝；明确不受限的SOURCE与找不到容量的链路是两种状态。不同VM即使同host也仍消耗端点资源；真正同VM本地引用才无网络服务。

## 最小运行生命周期策略

为避免把超出实现的能力混入声明，NF003最初选择以下明确策略：

- **释放**：`DEPENDENCY_READY_AT_OBSERVATION_V2`。工作流到达、当前控制依赖满足、目标VM固定后，在当前观察时刻选择来源并发起需求，不回溯父任务较早的完成时间。producer-eager预取需要独立发布通知与重试/到达门控，当前不冒称支持。
- **可见性**：`PER_FILE_SETTLEMENT_OBSERVATION_V2`。每个文件在内核处理其完成结算时可见；保留有效流体完成与实际观察时刻的区别，不从可选/截断trace推导运行正确性，不回溯修改目录。
- **合并**：同逻辑文件、同目标、重叠中的请求共用一次活动单播；保留不同Job尝试的等待者与引用观察。不同目标仍是不同传输。
- **计算门控**：只有全部所需文件在固定目标可见且控制依赖满足才能提交CPU；计算失败不表示缓存/VM丢失。失败Job中的成功Task输出不能被整体丢弃。
- **数值支持域**：后续选择/准入必须检查容量换算、独立速率、时延和绝对时刻可表示性；正有限输入本身不够。不能默许零进度事件循环，也不顺带修改旧求解器的已锁定行为。

## 新无争用对照

新对照保留相同的文件身份、释放/选择/可见性/去重规则及单流端点/链路上限，只取消跨流共享。不能替换成起点不同的旧pre-execution V1，也不能把物理容量全部移除。

机理测试使用同一组冻结来源/路径决策：两条100字节流共享10 B/s链路，独立服务各10秒，共享服务各20秒；单流和不共享链路的情况保持一致。完整DAG中缓存可见性随服务时刻变化，动态副本选择结果可能内生变化；未实现决策重放时，不宣称两次运行的路径历史完全固定或全DAG完成时间单调。

## 证据与接线门禁

V1的`V1_PARENT_OR_EXTERNAL_GROUP`、`MODELED_CONSTRAINED_SOURCE`和组级FCT不能被重新标为实际逐文件副本证明。新运行模型开放前，必须有独立版本的按文件/尝试/来源/路径/可见性证据，以及正确的配置重建、跨文件校验、rerun和显示路径；不只扩大V1允许列表。

SOURCE带宽与共享存储连接、必要输出上传属于NF004；受控在线VM分配属于NF005。TCP/ECN、复杂一致性协议、自适应路由和有限缓存淘汰仍不在本轮最小闭环内。
